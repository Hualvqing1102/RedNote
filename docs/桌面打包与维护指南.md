# RedNote 桌面版结构说明与维护 / 扩展指南

本文回答两类问题：
1. 桌面版(exe / 文件夹)是怎么组成的、数据放哪里；
2. 以后要维护、或给 Agent 加新能力/插件时，应该动哪些文件。

> 形态速览：**源码开发**（python 后端 + React 前端）与 **打包产物**（PyInstaller）是两套文件；
> 你在 Git 仓库里维护的是**源码**；`dist/` 下的 exe 只是"编译后的运行包"，改源码后需重新打包。

---

## 一、打包产物：文件夹版的结构

默认打包命令（文件夹版，快）：

```powershell
powershell -ExecutionPolicy Bypass -File build_exe.ps1
```

需要传统单文件 exe 时：

```powershell
powershell -ExecutionPolicy Bypass -File build_exe.ps1 -SingleFile
```

生成物：

```
dist/RedNote/                      # 文件夹版：RedNote.exe + _internal
├── RedNote.exe                    # 程序入口（双击它）
└── _internal/                     # PyInstaller 管理的依赖区（勿手工归类！）
    ├── frontend_dist/             # 前端构建产物(index.html + assets) —— 打包时注入
    ├── rapidocr_onnxruntime/      # OCR 引擎及其识别模型(ch/en)
    ├── app/ 、 *.pyd / *.dll / ... # Python 代码与第三方库、运行库
```

关键点：
- `_internal` 是 **PyInstaller 自动生成**的依赖目录，第三方库必须保持它的原始布局才能被正确加载，**不要按"功能"手工搬动文件**。
- 我们能自主归类的是：`frontend_dist`（前端）、模型数据（随库自带）、以及**运行期用户数据目录**（见下）。
- 单文件版 `dist/RedNote.exe` 与文件夹版**功能完全一致**，只是启动时多一步自解压（更慢）。

打包前置：`cd frontend; npm run build` 生成最新 `frontend/dist`；并且先退出正在运行的 RedNote（否则文件被占用会打包失败）。

## 二、运行期用户数据（重要：分类清晰，不在打包目录里）

exe 启动时若未指定，数据默认放：

```
%APPDATA%\RedNote\
├── rednote.db     # 全部业务数据：笔记/正文/注释/收藏夹/日历事件
└── settings.json  # AI Provider 配置：provider、各模型组的 model/base_url/api_key
```

- 可用环境变量 `REDNOTE_DATA_DIR` 覆盖到别处（备份时复制整个目录即可）。
- **API Key 只存在 settings.json，接口永不回传明文**（设置页可见"已配置/未配置"）。
- 设置页内置「备份数据库 / 导出 Markdown」，可随时逃生。

## 四、Agent 扩展指南（你接下来最关心的部分）

### 4.1 给现有"单篇 Agent"加一个新动作（如"润色/翻译/改写"）

三步走，每步都有测试：

1. **后端逻辑**：在 `app/services/agent.py` 加一个函数（复用 `provider.complete(system, prompt)` 模式），
   错误统一抛 `AgentError`（server 层会转 502）。
2. **路由**：在 `app/server.py` 的 Agent 段加 `POST /api/agent/xxx`，用 `_current_provider()`。
3. **前端**：`frontend/src/api/client.ts` 加 `api.xxx(...)`；在对应页面(如 NoteView/CollectView)加按钮调用。
4. **测试**：`tests/test_providers.py` 有"真实失败必须抛错不静默降级"的范式可仿照；前端加对应用例。

### 4.2 加一个新的"模型 Provider"（插件式，无需改业务代码）

系统已把"用哪个模型"做成可插拔：业务代码只面向 `providers.LLMProvider` 接口。
新增如 `zhipu(智谱GLM)` 需要动 4 个文件（都有先例可抄 DeepSeek/Qwen）：

1. `app/settings.py`：`PROVIDERS` 元组加名字；`DEFAULTS` 加该组默认(模型名/base_url/api_key)；`validate` 若走 OpenAI 兼容则无需改(已覆盖 `OPENAI_LIKE`)。
2. `app/services/providers.py`：`build_provider` 里，OpenAI 兼容厂商加进 `("openai","deepseek","qwen",...)` 一行即可；非兼容协议则写新 Provider 类。
3. 前端 `frontend/src/types.ts` + `frontend/src/views/SettingsView.tsx`（选项卡片 CARDS + 默认地址）+ `frontend/src/lib/provider.ts`（上云提示/标签）。
4. 测试：`tests/test_settings.py`、`tests/test_providers.py` 加对应断言。

不需要改动任何采集/笔记/Agent 业务文件。

### 4.3 未来做"全局助手 B"（对话+建笔记+排日历）

- 在现有 `agent.py` 里组织 **tool/动作函数**（检索笔记、create_note、create_event 都已具备底层 service）。
- 通过 `providers.build_provider` 拿真实模型，做 function-calling；Mock 环境下做确定性演示。
- 数据结构迁移沿用 `app/db.py` 的幂等 ALTER 范式（见下），老库自动兼容。

### 4.4 加新的"本地文档格式"

在 `app/services/fileparse.py`：`SUPPORTED_EXTS` 加后缀 + `parse_bytes` 加一个分支（例：`.epub` 用 zipfile 解 xhtml）。
前端 `frontend/src/views/CollectView.tsx` 的 `FILE_EXTS/ACCEPT_EXTS` 同步即可。
数据层/笔记层零改动。

### 4.5 加新的数据表或字段（迁移范式）

在 `app/db.py`：
- 新表直接写进 `SCHEMA`（全部 `CREATE TABLE IF NOT EXISTS`，幂等）；
- 给已有表加列：照抄现有"事件表补 recur 列"模式 ——
  `PRAGMA table_info(...)` 检查列名不存在时 `ALTER TABLE ... ADD COLUMN`，
  全部在 `init_db()` 里幂等执行，老库启动即自动升级，无需手动迁移。

## 五、前后端测试与提交规范（AGENTS）

- 后端：`.venv\Scripts\python.exe -m pytest -q`（当前 92 用例，全绿基线）
- 前端：`cd frontend; npm run test`（vitest）、`npm run typecheck`、`npm run build`
- 每次改动 → 更新/新增对应测试 → 全绿 → `git commit`（一条改动一个提交，便于回滚）
- 改完前端务必 `npm run build` 再重打包，桌面版才会生效。

## 六、常见维护操作速查

| 想做的事 | 做法 |
|---|---|
| 重打包(改代码后) | 先关掉 RedNote → `cd frontend && npm run build` → `build_exe.ps1` |
| 只要单文件 | `build_exe.ps1 -SingleFile` |
| 换数据目录/备份 | 复制 `%APPDATA%\RedNote` 整个文件夹 |
| 查运行日志 | exe 用 `--windowed` 无控制台；临时排障可设 `REDNOTE_DESKTOP_PORT` 并访问 `http://127.0.0.1:端口/api/...` |
| 忘记放了哪个模型 Key | 设置页看"已配置/未填 Key"，Key 明文只在本地 settings.json |

## 七、桌面层坑位记录（重要）

- **js_api 对象严禁反向持有 window 引用**：pywebview 自动暴露 `js_api` 时会递归遍历对象图
  （`webview/util.py get_functions`）。若 api 对象持有 window，遍历会一路进入 .NET 控件代理，
  每次 `getattr` 生成新代理对象绕过去重 → **无限递归、UI 线程等锁、窗口"无法响应"**。
  取窗口一律用 `webview.windows[0]`（`run_desktop.py` 的 `DesktopApi` 即此写法，勿改回）。
- pythonnet(.NET) 在受限沙箱/降权下会"拒绝访问"，打包的 exe 在正常桌面无此问题。
- PyInstaller 的 `_internal` 是自动管理的依赖区，不要手工归类其中的第三方库。
