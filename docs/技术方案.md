# RedNote 技术方案

> 依据 `docs/MVP方案.md` 与 `demo.html` 高保真原型产出。目标：把 Demo 落成可用的桌面应用，先跑通 M1「采集 → 本地存 → 笔记库」最小闭环，再逐步接真实抓取与 Claude API。

## 1. 目标与范围

- **M1**：项目骨架 + 网页采集（静态 HTML）+ SQLite 本地存储 + 笔记库 UI（搜索 / 标签 / 删除）
- **M2**：Agent 总结与追问（接 Claude API），保存笔记时附带原文概要 + 原文链接
- **M3**：全文检索打磨、体验优化
- **不在本期**：视频转写 ASR、RAG 向量检索、OCR、浏览器插件（见产品方案 Phase 2）

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | Tauri 2.x（Rust） | 打包小、内存低、系统能力（文件/托盘/剪贴板）好；**备选 Electron** |
| 前端 | React 18 + TypeScript + Vite | 与 Demo 的三视图结构一致 |
| 状态/路由 | Zustand + 视图状态机 | 沿用 Demo 的「采集/笔记库/详情」三视图切换，暂不引入 react-router |
| 样式 | 手写 CSS（CSS 变量 token） | 沿用 Demo 已确认的视觉语言（图书馆绿 + 索引卡片），不引入重型组件库 |
| 网页抓取 | reqwest + Rust 可读性解析 | 后端抓取可绕开 WebView 的 CORS 限制 |
| 本地存储 | SQLite（rusqlite）+ FTS5 | 单文件、好备份，笔记正文存 Markdown |
| Agent | Anthropic Messages API（Claude） | 统一 Provider 接口，便于日后换模型 / 加本地模型 |
| 测试 | Vitest（前端）+ cargo test（后端） | 呼应 AGENTS.md「交付前测试全部通过」的要求 |

**决策点**：Tauri 需要 Rust 工具链。若不想碰 Rust，可整体切换为 Electron + better-sqlite3（后端逻辑用 Node/TS 写），其余架构不变。此决策影响后端语言，不影响数据模型与接口设计。

## 3. 总体架构

```
┌───────────────────────────────────────────┐
│        React UI（Tauri WebView）           │
│   采集页 · 笔记库 · 详情/追问 · 编辑        │
│   Zustand store（前端状态）                │
└────────────────────┬──────────────────────┘
                     │ invoke（Tauri command，JSON 序列化）
┌────────────────────▼──────────────────────┐
│        Tauri Rust 后端（Core）             │
│  ┌──────────┐ ┌──────────┐ ┌───────────┐  │
│  │ 采集服务  │ │ Agent服务 │ │ 笔记服务   │  │
│  │ 抓取/解析 │ │ LLM Client│ │ CRUD/搜索  │  │
│  └────┬─────┘ └────┬─────┘ └─────┬─────┘  │
│       │  reqwest   │  reqwest   │ rusqlite │
└───────┼────────────┼────────────┼──────────┘
        ▼            ▼            ▼
   目标网页      Anthropic API   本地 SQLite 文件
```

- **UI 层**只负责渲染和用户交互，不做网络/存储，逻辑全部下沉到后端。
- **后端 Core** 按服务拆模块：采集、Agent、笔记（含标签/搜索）。
- 前端与后端通过 Tauri `invoke` 调用，命令签名见第 6 节。

## 4. 数据模型（SQLite）

```sql
CREATE TABLE notes (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  title           TEXT NOT NULL,
  summary         TEXT NOT NULL DEFAULT '',      -- 摘要
  content         TEXT NOT NULL,                 -- Markdown 正文
  points          TEXT NOT NULL DEFAULT '[]',    -- 要点，JSON 数组（M1 简单处理）
  source_url      TEXT NOT NULL DEFAULT '',      -- 原文链接
  source_snapshot TEXT NOT NULL DEFAULT '',      -- 原文正文快照（用于「附带原文概要」）
  created_at      INTEGER NOT NULL,              -- Unix 秒
  updated_at      INTEGER NOT NULL
);

CREATE TABLE tags (
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE note_tags (
  note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  tag_id  INTEGER NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (note_id, tag_id)
);

-- 全文检索（搜索标题/摘要/正文）
CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, summary, content,
  content='notes', content_rowid='id'
);
```

说明：

- `source_url` 与 `source_snapshot` 直接满足「保存时附带原文链接 + 原文概要」的诉求；详情页据此展示原文摘要。
- `points` 先以 JSON 存于 notes 表，M1 保持简单；若后续要点需要独立检索，再规范化为 `note_points` 子表。
- `notes_fts` 通过触发器或应用层在写入时同步，保证搜索一致。

## 5. 核心模块设计

### 5.1 采集服务（collect）

- 输入 URL → `reqwest` 发起 GET（带 UA、超时、限重定向）→ HTML 正文抽取（`readability` 或 `dom_smoothie`）→ 输出 `{ title, content, source_url }`。
- 失败处理：非 200、非 HTML、超时、解析失败 → 返回结构化错误，UI 给出可行动的提示（而非空白）。

### 5.2 Agent 服务（agent）

- 定义统一 Provider 接口（Rust trait）：

```rust
#[async_trait]
trait LlmProvider: Send + Sync {
    async fn chat(&self, system: &str, messages: Vec<Message>) -> Result<String, AppError>;
}
```

- `ClaudeProvider` 调 Anthropic Messages API；另实现 `MockProvider` 供测试与离线演示。
- **总结**：prompt 要求模型输出 JSON（`title/summary/points/tags`），`serde` 解析；解析失败时降级为纯文本摘要，不阻断流程。
- **追问**：把 `{笔记正文}` 作为上下文拼接进 system，返回一段引用笔记内容的回答。
- **API Key**：存本地应用配置目录（Tauri app config dir），不进 Git 仓库。

### 5.3 笔记服务（note）

- CRUD：`create / list / get / update / delete`（删除是用户明确要的功能，注意 `ON DELETE CASCADE` 清理 note_tags）。
- 搜索：`list` 支持关键词（走 FTS5）与标签过滤。
- 标签：保存时写入或复用已有标签，按标签筛选用 `note_tags` join。

### 5.4 前端

- 三个视图对应三个容器组件：`CollectView` / `LibraryView` / `NoteView`，用状态机切换（对齐 Demo）。
- 每个视图的交互、加载态、空态、错误态直接复用 Demo 已定的文案与视觉 token。

## 6. Tauri 命令接口

```rust
collect_url(url: String) -> Result<CollectOutput, AppError>
  // CollectOutput { title, content, source_url }

summarize(title: String, content: String) -> Result<SummaryOutput, AppError>
  // SummaryOutput { title, summary, points: Vec<String>, tags: Vec<String> }

create_note(input: NewNote) -> Result<Note, AppError>
  // NewNote { title, summary, content, points, source_url, source_snapshot, tags }

list_notes(filter: NoteFilter) -> Result<Vec<Note>, AppError>
  // NoteFilter { query: Option<String>, tag: Option<String> }

get_note(id: i64) -> Result<Note, AppError>
update_note(id: i64, patch: NotePatch) -> Result<Note, AppError>
delete_note(id: i64) -> Result<(), AppError>

ask(note_id: i64, question: String) -> Result<String, AppError>
```

## 7. 关键流程（采集 → 保存）

1. 用户在采集页粘贴 URL，点「提炼」。
2. UI 调 `collect_url` → 后端抓取 + 解析 → 返回原文 `{ title, content, source_url }`（此阶段 UI 显示「读取中」）。
3. UI 调 `summarize(title, content)` → 后端调 Claude → 返回结构化笔记 `{ title, summary, points, tags }`（UI 显示「提炼中」）。
4. UI 展示「原文摘录 + Agent 笔记」，用户确认后调 `create_note`，**同时写入 `source_url` 与 `source_snapshot`**。
5. 后端写库 → 返回 `Note` → UI 刷新笔记库。

追问流程：`ask(note_id, question)` → 后端读笔记内容 → 构造 prompt → 调 Claude → 返回回答。

## 8. 测试策略

- **后端（cargo test）**：数据模型 CRUD、采集解析（用本地 fixture HTML）、JSON 解析容错、`ClaudeProvider` 用 `MockProvider` 隔离。
- **前端（Vitest）**：组件渲染、状态流转、空态/错误态。
- **集成**：用 fixture HTML + MockProvider 跑通「采集 → 总结 → 保存 → 列表」全链路。
- **交付门槛**（AGENTS.md）：全部测试通过 + 手动过一遍 Demo 流程，才交付给用户。

## 9. 里程碑与实施顺序

- **M1**：初始化 Tauri + React + TS 骨架 → SQLite + 笔记 CRUD + 删除 → 采集（抓取 + 解析）→ 笔记库 UI（搜索 / 标签）。
- **M2**：Agent 总结 + 追问（ClaudeProvider + 统一接口）→ 详情页展示原文概要 + 原文链接。
- **M3**：FTS5 全文检索打磨 → 体验与视觉细节对齐 Demo → 打包发布（Tauri bundle）。

## 10. 风险与决策

- **Rust 学习成本**：若成本过高，切换 Electron（架构不变，仅后端语言改 TS/Node）。
- **动态网页 / 反爬**：M1 只支持静态 HTML；动态页后续用无头浏览器或第三方解析服务。
- **隐私与合规**：正文发送云端前在 UI 明示用户（已列入产品方案）。
- **API Key 安全**：本地存储、不进 Git；提供「清除 Key」入口。
