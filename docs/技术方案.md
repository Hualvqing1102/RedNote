# RedNote 技术方案

> 依据 `docs/MVP方案.md` 与 `demo.html` 高保真原型产出。技术栈已定：**Electron**。目标：跑通 M1「采集 → 本地存 → 笔记库」最小闭环，再逐步接真实抓取与 AI。

## 1. 目标与范围

- **M1**：项目骨架 + 网页采集（静态 HTML）+ SQLite 本地存储 + 笔记库 UI（搜索 / 标签 / 删除）
- **M2**：Agent 总结与追问（默认 Claude，可切换本地模型），保存笔记时附带原文概要 + 原文链接
- **M3**：全文检索打磨、体验优化、打包发布
- **不在本期**：视频转写 ASR、RAG 向量检索、OCR、浏览器插件（见产品方案 Phase 2）

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | **Electron**（已定） | 全 JavaScript/TypeScript，好维护、生态成熟；体积较大但可接受 |
| 前端 | React 18 + TypeScript + Vite | 与 Demo 的三视图结构一致 |
| 状态/路由 | Zustand + 视图状态机 | 沿用 Demo 的「采集/笔记库/详情」三视图切换 |
| 样式 | 手写 CSS（CSS 变量 token） | 沿用已确认的视觉语言（图书馆绿 + 索引卡片） |
| 网页抓取 | 主进程 `fetch` + `@mozilla/readability` + `linkedom` | 主进程无浏览器 CORS 限制 |
| 本地存储 | `better-sqlite3` + FTS5 | 单文件、好备份，笔记正文存 Markdown |
| AI 接入 | 统一 Provider 接口 | 内置 Claude + OpenAI 兼容端点，可接本地部署模型 |
| 测试 | Vitest（前端 + 主进程） | 呼应 AGENTS.md「交付前测试全部通过」 |

## 3. 总体架构

```
┌────────────────────────────────────────────┐
│        Renderer（React，渲染进程）           │
│     采集页 · 笔记库 · 详情/追问 · 编辑        │
│     Zustand store                          │
└───────────────────┬────────────────────────┘
                    │ contextBridge 暴露的 window.api（IPC 调用）
┌───────────────────▼────────────────────────┐
│        Main（Electron 主进程，Node.js）      │
│  ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │ 采集服务  │ │ Agent服务 │ │ 笔记服务    │  │
│  │ fetch+解析│ │ Provider │ │ CRUD/搜索   │  │
│  └────┬─────┘ └────┬─────┘ └─────┬──────┘  │
│       │ fetch      │ fetch/http │ better-sqlite3 │
└───────┼────────────┼────────────┼──────────┘
        ▼            ▼            ▼
    目标网页     Claude / 本地模型   本地 SQLite 文件
              （OpenAI 兼容端点）
```

- **渲染进程**只做界面和交互，不发网络请求、不碰数据库。
- **主进程**按服务拆模块：采集、Agent、笔记（含标签/搜索）。
- 两个进程通过 Electron IPC 通信（`contextBridge` + `ipcMain.handle`）。

## 4. 数据模型（SQLite）

```sql
CREATE TABLE notes (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  title           TEXT NOT NULL,
  summary         TEXT NOT NULL DEFAULT '',      -- 摘要
  content         TEXT NOT NULL,                 -- Markdown 正文
  points          TEXT NOT NULL DEFAULT '[]',    -- 要点，JSON 数组（M1 简单处理）
  source_url      TEXT NOT NULL DEFAULT '',      -- 原文链接
  source_snapshot TEXT NOT NULL DEFAULT '',      -- 原文正文快照（用于「附带原文概要」）
  created_at      INTEGER NOT NULL,              -- Unix 秒
  updated_at      INTEGER NOT NULL
);

CREATE TABLE tags (
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE note_tags (
  note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  tag_id  INTEGER NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (note_id, tag_id)
);

-- 全文检索（搜索标题/摘要/正文）
CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, summary, content,
  content='notes', content_rowid='id'
);
```

说明：

- `source_url` 与 `source_snapshot` 直接满足「保存时附带原文链接 + 原文概要」的诉求。
- `points` 先以 JSON 存于 notes 表，M1 保持简单；需要独立检索时再规范化为子表。
- `notes_fts` 通过触发器或应用层在写入时同步。

## 5. 核心模块设计

### 5.1 采集服务（collect）

- 输入 URL → 主进程 `fetch`（带 UA、超时、限重定向）→ 用 `@mozilla/readability` + `linkedom` 抽取正文 → 输出 `{ title, content, source_url }`。
- 失败处理：非 200、非 HTML、超时、解析失败 → 返回结构化错误，UI 给可行动的提示。

### 5.2 Agent 服务 + Provider 抽象（支持本地模型，重点）

统一接口：

```ts
interface LLMProvider {
  chat(opts: { system?: string; messages: Message[] }): Promise<string>;
}
```

内置实现：

- `ClaudeProvider` —— Anthropic Messages API。
- `OpenAICompatibleProvider` —— 任意 OpenAI 兼容端点（`baseUrl + model + apiKey`）。
  - 一套代码即可覆盖：**DeepSeek 云**、**Ollama**（`/v1`）、**LM Studio**、**vLLM**、本地部署的 DeepSeek 等。
- `OllamaProvider`（可选）—— 走 Ollama 原生 `/api/chat`，仅在有特殊需要时用。

`ProviderFactory` 按配置实例化，配置存本地 `settings.json`（Electron `app.getPath('userData')` 目录），不进 Git：

```json
{
  "provider": "openai-compatible",
  "baseUrl": "http://localhost:11434/v1",
  "model": "deepseek-r1:7b",
  "apiKey": "not-needed",
  "temperature": 0.3
}
```

- **总结**：prompt 要求输出 JSON（`title/summary/points/tags`），解析失败时降级为纯文本摘要，不阻断流程。
- **追问**：把 `{笔记正文}` 作为上下文，返回引用笔记内容的回答。
- **本地模型注意**：输出稳定性不如云模型，`temperature` 调低 + JSON 容错解析。

### 5.3 笔记服务（note）

- CRUD：`create / list / get / update / delete`（删除是明确需求，`ON DELETE CASCADE` 清理 note_tags）。
- 搜索：`list` 支持关键词（FTS5）与标签过滤。

### 5.4 前端

- 三个视图对应容器组件：`CollectView` / `LibraryView` / `NoteView`，状态机切换（对齐 Demo）。
- 加载态、空态、错误态、文案复用 Demo 已定的内容与视觉 token。

## 6. 接口（Electron IPC）

preload 脚本用 `contextBridge` 暴露 `window.api`，每个方法对应主进程一个 `ipcMain.handle`：

```ts
window.api.collectUrl(url)               // → { title, content, source_url }
window.api.summarize(title, content)     // → { title, summary, points, tags }
window.api.createNote(input)             // → Note
window.api.listNotes(filter)             // → Note[]
window.api.getNote(id)                   // → Note
window.api.updateNote(id, patch)         // → Note
window.api.deleteNote(id)                // → void
window.api.ask(noteId, question)         // → string
window.api.getSettings() / saveSettings(s) // 模型配置
```

## 7. 关键流程（采集 → 保存）

1. 用户在采集页粘贴 URL，点「提炼」。
2. UI 调 `collectUrl` → 主进程抓取 + 解析 → 返回原文（此阶段 UI 显示「读取中」）。
3. UI 调 `summarize` → 主进程按当前 Provider 调模型 → 返回结构化笔记（UI 显示「提炼中」）。
4. UI 展示「原文摘录 + Agent 笔记」，用户确认后调 `createNote`，**同时写入 `source_url` 与 `source_snapshot`**。
5. 主进程写库 → 返回 `Note` → UI 刷新笔记库。

追问流程：`ask(noteId, question)` → 读笔记内容 → 构造 prompt → 调当前 Provider → 返回回答。

## 9. 里程碑与实施顺序

- **M1**：初始化 Electron + React + TS 骨架 → SQLite + 笔记 CRUD + 删除 → 采集（抓取 + 解析）→ 笔记库 UI（搜索 / 标签）。
- **M2**：Agent 总结 + 追问（ClaudeProvider + OpenAICompatibleProvider）→ 详情页展示原文概要 + 链接 → 设置页（切换模型 / 本地模型地址）。
- **M3**：FTS5 全文检索打磨 → 体验对齐 Demo → 打包发布（electron-builder）。

## 10. 风险与决策

- **Electron 体积较大**：已接受；日后若在意体积，可迁移 Tauri，界面层可复用。
- **动态网页 / 反爬**：M1 只支持静态 HTML；动态页后续用无头浏览器或第三方解析。
- **本地模型效果/速度**：Provider 抽象已就位，换模型只改配置；接本地模型后可完全离线。
- **隐私与合规**：正文发云端前在 UI 明示用户；切换本地模型后无需联网。
- **API Key 安全**：本地存储、不进 Git；提供「清除 Key」入口。
